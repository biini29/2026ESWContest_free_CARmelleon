
# Arduino ↔ ROS 2 Serial Protocol

`arduino_bridge_node`(ROS 2)와 Arduino Mega(리니어 액추에이터 제어 펌웨어) 사이의 시리얼 통신 프로토콜 명세입니다.

---

## 1. 연결 정보

| 항목 | 값 |
|---|---|
| 장치 경로 | `/dev/arduino_linear` (udev로 고정) |
| 통신 속도 | 115200 bps |
| 부팅 시 응답 | `READY` |

---

## 2. 명령 프로토콜 (ROS → Arduino)

### 형식

```
M,<모터번호>,<방향>,<속도>\n
```

| 필드 | 범위 | 설명 |
|---|---|---|
| 모터번호 | 1~5 | Arduino 물리 모터 채널 (EN/IN 핀은 [`03_Pinout_Table.md`](../02_Design/electrical/03_Pinout_Table.md) 참고) |
| 방향 | -1, 0, 1 | -1=후진, 0=정지, 1=전진 |
| 속도 | 0~255 | PWM 듀티 (`PWM_SPEED = 200` 고정값 사용) |

### 예시

```
M,1,1,200      # 모터1 전진, 속도 200
M,3,-1,200     # 모터3 후진, 속도 200
M,2,0,0        # 모터2 정지
```

### 채널 ↔ 위치 매핑 (소프트웨어 보정)

Arduino 물리 모터 채널과 등받이 배치 위치(150/320/490/660/830mm)는 조립 과정에서 1·2번이 뒤바뀐 상태로 고정되어, `seat_controller_node`의 `MOTOR_MAP`으로 소프트웨어에서 보정합니다.

```python
MOTOR_MAP = [2, 1, 3, 4, 5]
# 배열 인덱스(0=150mm, 1=320mm, 2=490mm, 3=660mm, 4=830mm)
# → 실제 전송되는 Arduino 물리 모터 번호
```

즉 150mm 위치를 제어하려면 실제로는 `M,2,...`를 전송하고, 320mm 위치는 `M,1,...`을 전송합니다.

---

## 3. 응답 프로토콜 (Arduino → ROS)

```
OK M<모터번호> dir=<방향> spd=<속도>
```

예: `OK M1 dir=1 spd=200`

---

## 4. 리셋 시퀀스

`seat_controller_node`가 리셋 신호(`/target_seat_profile`의 `actuator_mm` 전체 0 이하)를 받으면:

1. 현재 위치(`current_mm`) 기준으로 모터별 필요 후진 시간을 계산 (가장 오래 걸리는 모터 + 여유 3초)
2. 모든 모터에 `M,<번호>,-1,200` 동시 전송
3. 계산된 시간만큼 대기
4. 2번 모터를 제외한 나머지 모터에 정지 명령(`M,<번호>,0,0`) 전송
5. 3초 추가 대기 후 2번 모터에 정지 명령 전송 (조립 특성상 2번 모터가 더 오래 걸림)
6. `current_mm`을 전부 0으로 초기화

> 위치 센서(엔코더)가 없는 시스템이므로, `current_mm`은 마지막으로 전송한 목표값을 소프트웨어에서 추적한 값입니다. 전원이 재시작되면 이 값도 초기화되어 실제 물리 위치와 어긋날 수 있어 재시작 시 리셋 절차가 필요합니다.

---

## 5. 알려진 제약 및 주의사항

- **위치 피드백 없음**: 모든 위치 제어는 "모터별·방향별 실측 속도(mm/s) × 목표 이동거리 = 구동 시간"으로 시간 기반 추정됩니다. 배터리 전압 변화, 기계적 마찰 변화 등에 따라 오차가 누적될 수 있습니다.
- **동시 명령 시 시리얼 지연**: 5개 모터에 순차적으로 명령을 전송하므로, 아주 짧은 시차가 발생합니다 (실사용에 영향 없는 수준).
- **스케치 무결성**: Arduino에 다른 스케치가 올라가 있으면 이 프로토콜 자체가 응답하지 않습니다. `READY` 부팅 메시지 확인으로 검증 가능합니다.
